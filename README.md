# aireadingbook

Folio · 읽고, 듣고, 간직하는 서재

첨부된 북카페 디자인을 참고한 로컬 구현. GitHub → Vercel 배포와 Firebase 인증·저장소를 연결하는 방향으로 구성했습니다. Sites 서비스는 사용하지 않습니다.

## 실행

Node.js 22 이상에서 `npm start`, 이후 http://localhost:4173 접속. Windows에서는 기존 `Start-Folio.cmd`도 사용 가능합니다.

`npm run check` 또는 `npm run build`는 네트워크 없이 구문·자산·배포 설정·AI 실행 차단을 검사합니다. 정적 결과물은 `dist/`입니다. 필요한 PDF.js와 PageFlip은 이미 `dist/vendor/`에 포함되어 있습니다.

## 현재 구현

- 북카페 라운지, 생성한 카페 배경 이미지와 네 종류의 표지, 모바일 접이식 메뉴.
- 기존 PDF/이미지/TXT/Markdown 업로드, 책장 넘김, 확대/축소, 마지막 읽은 위치 유지.
- 읽고 있는 책·찜·내가 올린 책 분류, 마이페이지, 발췌 및 페이지 책갈피.
- 텍스트 책에서 문장 선택 모드를 켜고 드래그 → 발췌 저장. 텍스트 PDF는 추출 패널에서 선택. 스캔 PDF는 페이지 이미지로 읽을 수 있지만 OCR 전에는 발췌할 텍스트가 없습니다.
- 운영체제에 설치된 오프라인 음성을 이용한 현재 페이지 읽기 및 텍스트 줄 강조. 해당 언어의 로컬 음성이 없으면 실행하지 않습니다. 고품질 AI 나레이션과는 별도입니다.
- MediaRecorder 마이크 녹음, 브라우저 저장, 재생 및 파일 다운로드. 최대 10분. 녹음 장치와 브라우저 권한이 필요합니다.
- 라이트/다크, 독서 조도, 종이 테마. 영어는 주요 메뉴 미리보기만 구현되어 전체 번역은 아직 아닙니다.
- 로컬 운영 대시보드: 현황, 도서 메타데이터, 출처 및 권리 검수 기록, 로컬 전시 상태, 제작 승인 대기 목록, 역할 정책 안내.

데이터는 기존 `folio-library` IndexedDB를 유지합니다. 기존 업로드를 삭제하거나 초기화하지 않습니다. 로컬 데이터는 같은 브라우저·동일 출처에서만 보이며 브라우저 데이터를 지우면 사라집니다.

## Firebase 설정 준비

사용자가 제공한 `automovie-4498a` 웹 앱 설정은 `dist/firebase-config.js`에 반영했습니다. 운영 대시보드의 사용자·권한 탭에서 설정된 프로젝트와 실제 연결 여부를 구분해서 표시합니다. Google 로그인·로그아웃과 상태 복원을 연결했습니다. Analytics, DB 및 파일 업로드는 활성화하지 않았습니다. 로그인한 사용자도 현재 브라우저의 공용 로컬 서재를 사용하며 계정별 클라우드 동기화는 아직 없습니다. 자세한 설정과 허용 도메인은 [Google 로그인 안내](docs/GOOGLE-LOGIN.md)를 참고하세요.

이 설정만으로 현재 요금제, 버킷 리전, 무료 잔여 한도, 관리자 권한 또는 서비스 활성화 여부를 확인할 수는 없습니다. 실제 서비스 사용 전 비용 조건과 승인 범위를 확인해야 합니다. 기존 프로젝트의 다른 앱에 영향을 줄 수 있으므로 현재 준비된 보안 규칙을 원격에 덮어쓰지 않았습니다. 연결 절차는 [Firebase 연결 메모](docs/FIREBASE.md)를 참고하세요.

## 아직 연결하지 않은 기능

Firestore/Storage, 실제 관리자·제작자 권한 검증, 서버 동기화, 고전 원문 수집·권리 검수·번역, AI 표지/나레이션/OCR, 타임코드 기반 음원 재생, 온라인 발행, 전체 다국어, 실서비스 운영 대시보드입니다. 현재 어드민은 명확히 표시된 **로컬 미리보기**이며 실제 관리자 보안 경계가 아닙니다.

`api/production-jobs.mjs`는 모든 POST 요청을 503으로 거절합니다. 클라이언트가 관리자 역할이나 승인 값을 전달해도 AI 작업을 실행하지 않습니다. 자동 재시도, Cron, 유료 공급자 fallback은 없습니다.

## 배포 준비

GitHub 대상은 `jejuailabs/aireadingbook`이며, 사용자 설정에 따라 푸시 시 Vercel 자동 배포가 시작됩니다. `vercel.json`은 `dist`를 배포 대상으로 지정합니다. `firebase/`의 규칙은 연결 전 초안이며 에뮬레이터 검증·실제 권한 테스트 전에는 운영 배포하지 않습니다. 공개 카탈로그와 생성 작업은 클라이언트 직접 쓰기를 차단하고 서버에서만 처리하도록 설계했습니다.

**사용자의 상시 비용 승인 조건:** 서비스별 과금 여부, 무료 한도·초과 조건, 예상 비용, 자동 갱신 여부를 확인하고 해당 범위에 대한 명시적인 승인을 받은 후 배포·저장소·AI를 활성화합니다. 현재 배포나 계정 생성, 과금 활성화는 하지 않았습니다.

## 검증

카페 홈 화면, 검색, 모바일 메뉴와 관리자 화면 이동, 다크 모드를 브라우저에서 확인했습니다. 구글 인증 상태와 나레이션 제작기는 외부 유료 호출 없이 모의 테스트합니다. 실제 Google 계정 로그인, 리더·발췌·녹음 전체 시나리오는 별도 실사용 검증이 필요합니다. `npm run check`는 구문/설정/차단 정책 검사이며 브라우저 E2E나 Firebase 규칙 에뮬레이터 검사를 대신하지 않습니다.

상세 기능, 데이터 구조, 다음 단계는 [제품 및 구현 계획](docs/PRODUCT.md)을 참조하세요.

## RunPod 책 나레이션 사전 제작

prompt 프로젝트의 Qwen3-TTS 1.7B / Sohee를 재사용하는 일괄 제작 도구를 추가했습니다. 어드민에서 여러 책의 원고 묶음을 내려받고, 로컬 CLI에서 승인된 범위로 순차 생성한 뒤 완성 음원 폴더와 제작 리포트를 가져옵니다. 실행 시간·음원 길이·추정 원가를 따로 기록합니다. 현재 `NARRATION_ENABLED=false`이며 실제 유료 생성은 하지 않았습니다. 공개 생성 API는 계속 비활성이고, Firebase 계정 권한과 클라우드 저장 연동은 별도 작업입니다.

- 오프라인 검증: `npm test`
- 준비: `npm run narration:prepare -- <원고.json>`
- 상세 사용법과 비용: [나레이션 제작 안내](docs/NARRATION.md)

키·승인·원고·음원이 들어가는 `.env.local`과 `data/`는 Git에 포함하지 않습니다. Vercel 설정은 변경하지 않았습니다.
